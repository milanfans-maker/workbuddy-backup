# Hypit 视频复刻工作流

**先决条件**：`hypit-deploy`（装好 CLI 与 Runtime）与 `hypit-comfyui-provider`（接上本地生成后端）已完成。
本文是 2026-09-21 在 macOS 上复刻两支参考片（国风 47s、冬雪油画 191s）后沉淀的方法论。

## 核心认知：复刻 ≠ 抄描述

**最大的坑是照着参考片写内容描述。** 模型会完美复现你写的内容，却丢掉让原片好看的那套机制。
正确做法是先把参考片拆成 **机制**（光比、节奏、材质、运动类型），再用自己的内容重新落在同一套机制上。

两支片子都验证过：v1 逐镜照抄内容 → 看着"对"但美学跑偏；v2/v3 改按机制写 → 立刻贴近。

## 阶段 0：参考片逆向解读

```bash
# 1. 参数与时长
ffprobe -v error -show_entries format=duration -show_entries stream=codec_type,codec_name,width,height,r_frame_rate \
  -of default=noprint_wrappers=1 source.mp4

# 2. 有没有人声（决定要不要配旁白/字幕）
ffmpeg -hide_banner -i source.mp4 -map 0:a -af volumedetect -f null - 2>&1 | grep -E "mean_volume|max_volume"
ffmpeg -hide_banner -i source.mp4 -map 0:a -af "silencedetect=noise=-35dB:d=1.5" -f null - 2>&1 | grep -oE "silence_(start|end): [0-9.]+"

# 3. 镜头切点
ffmpeg -hide_banner -i source.mp4 -filter:v "select='gt(scene,0.25)',showinfo" -f null - 2>&1 \
  | grep -oE "pts_time:[0-9.]+" | sed 's/pts_time://' | tr '\n' ' '
```

### ⚠️ scene-detect 阈值陷阱（必踩）
**高阈值必然漏检。** 相邻镜头色调相近时（例如整片都是冷蓝），`scene>0.3` 只报一部分。
**判据**：用 0.10 / 0.14 / 0.18 三档分别跑，**三档结果一致才是真值**。不一致就继续降。
补充判据：如果算出的「平均每镜时长」落在 5.0–6.2 s 附近且非常均匀，基本可以确认是 AI 图生视频拼片（固定时长输出），这就是正确切点数。

### 全片概览与逐镜代表帧
```bash
# 概览网格（每 4s 一帧）
ffmpeg -v error -i source.mp4 -vf "fps=0.25,scale=240:-1,tile=8x6:padding=3:color=white" -frames:v 1 overview.jpg -y

# 逐镜代表帧 → 拼网格（用 image2 序列，比 glob 多输入可靠）
ffmpeg -v error -start_number 1 -i /tmp/s%02d.jpg -vf "tile=4x4:padding=6:color=white" -frames:v 2 -y "shotsgrid-%d.jpg"
```

### 运动类型判定
抽某个长镜头的 0/25/50/75/100% 帧纵向拼 1×5，看是**相机运动**还是**内容形变**。
这个判断决定提示词里写不写镜头运动，写错会让画面整体漂移。

## 阶段 1：机制抽象

写进 `ANALYSIS.md` 的应该是这类东西，而不是"第 5 个镜头有只猫"：

- **光比配方**：冷色占多少面积、暖色出现在哪、亮部在哪
- **材质统一手段**：31 个无关场景靠什么串成一本画册（通常是同一套笔触 + 同一套色板）
- **运动类型**：微动（雪落/云移/光摇曳）还是叙事动作——治愈系几乎全是前者
- **情绪曲线**：暖色从第几镜开始爬升、峰值在哪、有没有"唯一例外镜"
- **节奏指纹**：每镜时长是否均匀 → 决定要不要变速/补帧

同时输出 `TIMELINE.md`（逐镜表：画面 / 光源 / 运动 / 段落归属）与 `BRIEF.md`（范围与硬约束）。

## 阶段 2：提示词纪律 ⭐ 最重要（十三条，含六条血泪教训）

先读官方 `~/.workbuddy/skills/hypit/references/playbooks/craft/video-direction.md`，它明确警告"比喻性措辞被字面化"。

### 纪律 1：只用具体可见语言，不用比喻
写「时光的河流」→ 模型画一条河。写「像母亲的手一样温暖的光」→ 得到一只手。
**把比喻翻译成物理事实**：「柔和的暖光从右上方来，在毛边形成一圈不刺眼的轮廓光」。

### 纪律 2：颜色词会被放大成饱和色块
**这是最反直觉的一条，两支片子都踩到。**
写「深绿雪松」→ 得到**荧光翠绿**；写「暖黄窗光」→ 暖色面积失控占满全屏。
**正确写法是描述颜色的成因与状态，而不是它的名字**：

| ❌ 不要写 | ✅ 改写成 |
|---|---|
| 青绿色的溪流 | 灰蓝色的溪流 |
| 深绿色的雪松 | 树干与树冠被厚雪压着，绿色只是雪层之间露出的一点点暗灰绿 |
| 明亮的红褐色松鼠 | 暗沉发灰的红褐与灰奶油色相间，颜色是掺了灰的暖色 |
| 暖橙色的夕阳 | 被浓雾包裹的灰橙，光芒很弱，几乎溶进天空里 |

**根因**：模型对色相名词的响应是"给出该色相的纯色"，而不是"给出该色相的暗调版本"。

### 纪律 3：材质要**短促肯定**地写在开头，不要写成长段

> ⚠️ **2026-09-21 实测教训（v3 全片翻车）**：把材质写成 400 字的详细段落、并把「必须避免：照片的锐利清晰、3D渲染的光滑质感、数码喷枪的柔焦模糊…」这类**否定清单**写进提示词，
> 结果 12 镜**全部**变成高清数字插画 —— 比改之前更不像油画、更饱和、更锐利。
> **否定清单里的词本身会被强化**（写「避免照片」→ 得到照片级清晰度；写「不出现橙色」→ 橙色更多；写「不出现平整干净的色面」→ 色面更干净）。
> 文本编码器是 Qwen3-VL（LLM 级），900 字不会被截断，所以**不是长度截断问题，是否定语义被放大**。

**正确做法**：把材质压成**开头第一句的肯定式强断言**（开头权重最高），然后立刻进入具体画面。
```
低饱和度的厚涂油画，粗犷的笔触清晰可见，画面笼罩在冷灰的雾气里，颜色灰暗柔和。
```
一句话搞定材质 + 饱和 + 大气三件事，约 40 字。**不要展开成段。**

> ✅ **笔触是能出来的**（2026-09-21 笔触专项实验，4 变体单变量对照）。同一镜、同一主体描述，只换开头材质句：
> | 变体 | 写法 | 天空纹理能量 | 色彩数 |
> |---|---|---|---|
> | A | 短肯定断言「低饱和度的厚涂油画，粗犷的笔触清晰可见」 | 16.59 | 2357 |
> | B | 英文术语 `thick impasto brushstrokes, palette-knife texture, canvas grain` | 22.85 | 1688 |
> | C | 画派名 + 笔触位置穷举「每一处都能看到颜料的堆叠与笔刷拖痕——雪面、树冠、水面」 | 19.86 | 2710 |
> | D | 亚麻布 + 方向感「画在粗糙亚麻布上，宽笔刷厚厚堆叠，笔触带明确方向感」 | 13.28 | 2044 |
>
> **四种写法全都有可见笔触**，B 最粗、C 平衡最好。**A 是最低成本的可用解**。
> ⚠️ **但这不代表写不出来就够了** —— 见纪律 8，真正的差距在"笔触的**分布**"。

### 纪律 4：色板只写正向白名单，不写黑名单
❌ `不出现红色、橙色、翠绿、荧光色、纯黑、纯白`
✅ `画面只用灰蓝、灰青、灰白、灰褐这几种低饱和的颜色`

同理不要写比例数字（「暖色不超过四分之一」）—— 数字会把「暖色」这个概念塞进提示词。

#### ⚠️ 但白名单有明确的失效边界：管不住**小面积极端色**
实测：明明写了白名单（灰蓝/灰青/灰白/灰褐），S1 的人物还是围上了一条**鲜红围巾**，
S7 的雪地背景还是冒出了**橙红色枝叶**——占比不到 2%，但视觉上极抢眼。

**更有效的手段是「指定关键物体的颜色」，而不是给整幅画定色板**：
```
✅ 戴着深蓝灰色的毛线帽，围着米白色的厚围巾     ← 指定，模型会照做
❌ 不出现红色围巾                                ← 禁止，反而激活
```
再加一句**排他式正向句**封锁新元素：`整幅画面只有这几种颜色。`
（注意：这句只列数量、不点名任何颜色，所以不会像「不出现橙色」那样反向激活。
 反面例子见纪律 6 的比例数字——那里点的是"暖色"这个名字，就会激活暖色。）

> 通用规律：**凡是你想"排除"的东西，都要转成"指定另一个更具体的替代物"。**
> 想排除红色 → 指定"米白色围巾"；想排除照片感 → 指定"厚涂油画 + 可见笔触"。

### 纪律 5：负向排除只对**具体物件**有效，对**风格词**无效
- 有效（物件级、封闭式）：`画面里没有任何建筑、屋顶、围墙、栅栏、招牌或红色物体`
- **无效甚至有害（风格级）**：`不是照片、不是3D渲染、不是卡通、不是矢量插画` → 反向激活

### 纪律 6：长度纪律 —— 比你想的短
| 版本 | 平均字符 | 结果 |
|---|---|---|
| v2 | 456 | 油画感成立，但偏暖偏艳偏锐 |
| v3 | 928（2.03×） | **崩坏成高清插画 + 更艳** |
| v4 处方 | **230–260**（比 v2 更短） | 待验证 |

**判断依据**：约束堆得越多、越具体，画面越"干净锐利"——因为那些形容词本身构成了「高清细节」的语义。
**要压暖、压饱和、加朦胧，靠的是（a）换掉触发暖色的名词，而不是禁止暖色；（b）开头一句正向基调。**
例如落日：❌「不出现橙色」→ ✅ 直接把太阳写成「**一团被浓雾裹住的白灰色圆盘，光芒很弱**」——去掉暖色触发词比禁止暖色有效得多。

### 纪律 7：反面教材留档 —— v3 用的长模板（**不要照抄**）

下面这套模板是 v3 用的，**已被证伪**，留在这里是为了让你认出这个坑：

```
质感：这是一幅手工绘制的油画，不是照片。画面各处都能看清油画笔触——
宽笔刷铺出的块面、调色刀刮出的厚涂颜料堆叠，笔触有明确方向、长短交错、彼此覆盖；
颜料厚的地方能看出颜料的凸起与边缘的堆积，薄涂处隐约透出画布的经纬纹理；
物体的边界由笔触的断开与交叠形成，没有平滑连续的轮廓线；
相邻颜色之间有湿润的渗透与横向拖笔过渡。
必须避免：照片的锐利清晰、3D渲染的光滑质感、矢量插画的均匀色块、
数码喷枪的柔焦模糊、卡通描边、景深虚化与散景。
深色区域与高光区域同样保留可见笔触，画面里不出现平整干净的色面。
```
**它做对了什么**：写"笔触"本身是对的，方向正确。
**它做错了什么**：① 400 字的展开把画面语义推向"高清细节"；② 「不是照片 / 避免3D渲染的**光滑**质感 / 不出现**平整干净**的色面」把这三个词直接喂给了模型 —— 实测结果就是照片级清晰 + 光滑 + 干净色面。

同样被证伪的还有：
- 「色彩：冷色占画面约四分之三；暖色总面积不超过画面四分之一…」→ 比例数字无效
- 「不出现鲜艳的红、橙、翠绿、草绿、黄绿与任何荧光色」→ 橙色反而变多

### 纪律 8：⭐ 笔触要写"梯度"，不是写"全画面都有笔触"

**这是 2026-09-21 花了三轮才定位到的真因。**

把天空区放大 3 倍后对比，结论完全反直觉：

| | 近景/主体 | 远景/天空 |
|---|---|---|
| **参考片** | 笔触清晰（水面的横向刮刀痕、树冠的块状堆叠） | **平滑、无笔触、纯雾面** |
| **我们的 v2/v3/v4** | 有笔触 ✅ | **笔触照样铺满** ❌ |

也就是说：**我们的笔触比参考片还多**，而且是"平均分布"的。参考片是**传统油画的空间逻辑**——笔触随距离衰减，远处溶进雾里。
这个「均匀铺满的质感」正是画面读起来像**数字插画**而不是**手绘油画**的真正原因。

**处方：材质句要给出衰减方向**
```
厚涂油画，笼罩在冷灰的雾气里。……（材质句）
近处的笔触粗犷，越远的景物笔触越平缓，最后溶进雾里变成柔和的灰面。
```
> 第一句给材质与基调，第二句给**衰减**。第二句是 v5 新增的关键变量。
> ⚠️ 但注意：`画面每一处都能看到颜料的堆叠与笔刷拖痕` 这句在暗示**笔触均匀铺满全画面**，
> 与"梯度"是相互抵消的。v7 已把它删掉，换成下面纪律 9 的**尺度**描述。

### 纪律 9：⭐⭐ 笔触要写**尺度**——大笔触才能让形态消融（最后一层窗户纸）

**这是 2026-09-21 版 v6 放大核查后才看清的真因，比纪律 8 更根本。**

把参考片和我们成片的**同一块局部**并排放大到 100%，差距不在"有没有笔触"、也不在"梯度"，
而在**每一笔有多宽**：

| | 参考片 | 我们的 v2–v6 |
|---|---|---|
| 水面 | 一条横向刮刀痕横跨约 **1/6 画面宽**，几笔铺满整片水 | 无数条 30–50px 的细笔触 |
| 树冠 | **几乎不成形**的抽象色块堆叠，枝杈被省略 | 清晰的雪松轮廓，每根枝都被描出来 |
| 猫毛 | 一缕毛发就是**一整笔**，分缕被省略 | 照片级的细密短毛 |
| **尺度比** | 基准 | **细 5–10 倍** |

**后果**：笔触小 → 物体轮廓完整、细节齐全 → 读起来是**高清数字插画**；
笔触大 → 细节被省略、形状只靠色块边界交代 → 读起来才是**手绘油画**。
"细节太齐全"本身就会把画面推向插画，这与饱和度、暖色**无关**。

**处方：材质句里给出笔触的物理宽度，并声明细节被省略**
```
厚涂油画，笼罩在冷灰的雾气里。用一把很宽的排笔画成，每一笔都又宽又长，
一笔能横跨画面约六分之一，细小的纹理被省略、形状只靠笔触的边界交代。
近处的笔触粗犷，越远的景物笔触越平缓，最后溶进雾里变成柔和的灰面。
```
> 三个必写要素：**笔的宽度**（"很宽的排笔"）+ **笔触的物理尺寸**（"横跨画面约六分之一"）
> + **细节被省略**（"形状只靠笔触的边界交代"）。只写"粗犷""厚涂"这类形容词是不够的，
> 模型会把它们理解成"质感强但笔触小"。
> 毛发类主体改成「一束毛发就是一整笔，细小的分缕被省略」。
>
> ⚠️⚠️ **本条单独使用是无效的**——v7 按这个处方写全了三要素，结果毫无变化。
> 因为主体层仍在要求细节（"细密的短笔触""写实自然"），**局部事实否决了全局风格声明**。
> **必须配合纪律 11：把主体层的措辞也改成同方向。**

### 纪律 10：质感必须在 100% 或放大后判读 —— 缩略图会骗你

> ⚠️ **血泪教训**：我曾在一张 330px 宽的 3×4 对照网格上判定"四个版本的笔触都没出来，这条路走不通"，
> 于是去做笔触专项实验。但把同一帧放到 100% 并 3 倍放大后 —— **笔触清清楚楚地在那里**。
> 缩略图上的笔触和画布纹理会被降采样抹平，只剩"干净/锐利"的整体印象。
>
> **规则**：判断"有没有质感/笔触/颗粒/雾化"这类**高频细节**，必须
> ① 放到 100% 原分辨率，或 ② 裁一块局部 2–3 倍放大再看。
> **批次对照图只用于判断构图、色调、明暗这类低频特征。**
> 反过来也要注意：如果把"放大后能看到的笔触"当成"整体成立"，会漏掉真正的全局问题。

### 纪律 11：⭐⭐ 材质层与主体层必须**同向** —— 主体层的局部要求会**否决**材质层

**这是 v7 验证出来的、比纪律 9 更靠底层的一条规则。**

v7 在材质句里写了完整的"大笔触"三要素（纪律 9 的处方），结果**毫无效果**——
放大看，雪松的枝杈照样一根根描出来，猫毛照样是照片级细毛。查提示词才发现原因：

```
材质层：…用一把很宽的排笔画成…一束毛发就是一整笔，细小的分缕被省略…
主体层：毛发是柔和的橘色与奶油白色，用蓬松的短笔触画出，身体结构写实自然。
                                                    ↑ 直接否决了材质层
```

**同一个 prompt 里的两条冲突指令，模型听的是"离物体更近"的那条（主体层）。**
材质层是全局风格声明，主体层是局部事实陈述 —— 局部事实优先。

而"细密的短笔触""写实自然""每一根细枝都被白霜包裹""草茎的笔触清晰可辨"
这类**在主体层要求细节完整**的措辞，恰好是"插画感"的源头。

**处方：主体层不能出现任何要求细节完整的措辞，要改成抽象化要求。**

| ❌ 主体层（要求细节） | ✅ 主体层（要求省略） |
|---|---|
| 毛发用细密的短笔触画出蓬松感，身体结构写实自然 | 毛发只交代蓬松的体积与整块的颜色，不逐根描画细毛 |
| 每一根细枝都被厚厚一层白霜包裹 | 枝条被白霜裹成一片泛白的模糊轮廓，不描画细枝 |
| 岸边立着成排高大的雪松，树干与树冠被积雪压着 | 雪松只交代被雪压住的深色团块大形，不描画细枝与树形轮廓 |
| 草茎的笔触清晰可辨 | 草茎只有几笔粗放的交叉笔触，交织成一片粗粝色块 |

**自查方法**：写完提示词后，用关键词扫一遍**主体层**（不是材质层）——
`写实` `清晰可辨` `细密` `细小的笔触` `每一根` `逐根` `细腻`。
命中任何一个，材质层的笔触尺度指令就会被它抵消。

> ⚠️⚠️⚠️ **2026-09-21 晚 v8 证伪**：按上表把 **8 处**主体层措辞全部改成"只交代大形、不描画细枝"，
> 自查脚本全绿，结果是 —— **一个像素都没变**。v6 / v7 / v8 三版放大后肉眼不可分。
> 所以本条描述的"层间优先级"机制**可能成立，但剂量远不足以翻盘**：
> 真正的主导因素不是措辞同向，而是**模型对"命名主体"的细节先验**（见纪律 12）。
> **不要再在主体层措辞上加码。** 三版实验（v3 / v7 / v8）已证明这条路到了尽头。

### 纪律 12：⭐⭐⭐ 减法型指令**基本无效**，只能靠换通道

**v3 / v7 / v8 三次独立实验的共同结论。** 把"笔触尺度差 5–10 倍"这件事当成一个**减法**
（省略细节 / 缩小细节总量 / 别太锐），无论怎么改措辞都推不动：

| 版本 | 减法型措辞 | 结果 |
|---|---|---|
| v3 | 大量否定清单「避免照片的锐利清晰」「不出现橙色」 | 反向强化：更清晰、橙色更多 |
| v7 | 材质层写全「大笔触三要素 + 细节被省略」 | 无效（被主体层否决） |
| v8 | 主体层也改成「只交代大形、不描画细枝」（8 处） | **完全无效，零变化** |

反过来，**加法型措辞全部有效**（实测）：

| 加法型杠杆 | 效果 |
|---|---|
| 排他式正向白名单「整幅画面只有这几种颜色」 | 色相分散 95.5 → 12.3（橘猫镜） |
| 「保留固有色浓度、不压成一片灰」 | 饱和 55.3 → 169.5 |
| 大气透视梯度「越远的景物笔触越平缓，最后溶进雾里」 | 纹理对齐参考片 |
| 指定关键物体的颜色「米白色围巾 + 深蓝灰帽子」 | 修掉小面积极端色 |

**为什么**：模型把"猫 / 冷杉 / 干草"这类**命名主体**当作现实对象，会无条件还原其
**自然细节密度**；同一段文字里再要求"只交代大形"被当成噪声丢弃。
"纹理能量"这类指标在 v8 里 18.5 → 20.0，说明细节甚至没减少一点点。

> **行动准则：当差距是"东西太多/太细/太锐"时，不要在提示词里加码，直接换通道（纪律 13）。**
> 只有当差距是"缺了什么"（缺色、缺雾、缺光）时，才在提示词里加。

### 纪律 13：⭐⭐⭐ 先查**通道边界**，再动提示词 —— 减法只能靠换通道

**2026-09-21 查 `provider.js` 源码得到的硬事实。** 提示词通道只有"文生视频"一条时，
你能调的只有措辞；但 H3 还有一条**参考主体**通道，走的是**另一套 checkpoint**。

三套 Surface（作者侧元素 → 权重）：

| 通道 | 作者侧写法 | 权重 | 本部署 |
|---|---|---|---|
| 文生视频 | `<h3:TextVideo prompt={p} duration="5" resolution="768P" aspect-ratio="16:9"/>` | FL2VA | ✅ |
| 参考主体 | `<h3:ReferenceVideo prompt={p} …><h3:Reference image={ref}/></h3:ReferenceVideo>` | **Ref2VA** | ✅ |
| 首尾帧 | `<h3:FrameVideo prompt={p} first-frame={a.image} last-frame={b.image}/>` | FL2VA | ❌ 未接线 |

参考图这样声明（`@hypit/media`，相对元素所在文件的路径）：
```xml
<media:Image id="ref05" src="../references/source/frames/s05.png"/>
<h3:ReferenceVideo id="shot1" prompt={p1} duration="5" resolution="768P" aspect-ratio="16:9">
  <h3:Reference image={ref05}/>
</h3:ReferenceVideo>
```
> 属性名是 `image=`，值是**裸 id**（`{ref05}`，不是 `{ref05.image}`）；`media:Image` 输出 blob 并挂在裸 id 上。
> 改完先 `hypit check <author.svml>`（不花 GPU），再 `hypit plan <run.svrun>` ——
> plan 里会写明 `1 image reference`，这是"通道确实被选中"的证据。

**怎么查自己部署支持哪些通道**：读 Provider 源码里的 `serviceSupport()` 和 `WEIGHTS`，别猜。
本机位置：`<workspace>/packages/provider-comfyui-h3/dist/provider.js`。
里面还有几条会影响复刻的常量：`refMaxSize: 864`（参考图统一降采样，大笔触不受影响）、
`steps: 4` / `sampler: res_multistep` / `shift_video: 12.0`、`concurrency: 1`（请求串行）。

> **决策准则**：差距是"**多了什么**（细节/锐度/杂色）"→ 换通道；
> 差距是"**少了什么**（雾/光/色）"→ 加提示词。见纪律 12 的对照表。

#### ⚠️⚠️⚠️ 换通道前必看：**权重版本号**（2026-09-21 v9 实测）

`ReferenceVideo` 名字好听，但**本部署的 Ref2VA 是残的**。看 `WEIGHTS` 里的 LoRA 版本：

```js
fl2va:  lora: "minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors"   // v1.0
ref2va: lora: "minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors"      // v0.1 ← 早期版
```

4 步采样 + **v0.1 的 turbo LoRA** → 输出必然欠细节。实测（2 镜定标探针，配对口径 1024×576）：

| 版本 | 纹理能量 | 亮度对比 | 平均饱和 | 色相分散 |
|---|---|---|---|---|
| 参考片 | 16.05 | 56.6 | 148.0 | 25.6 |
| 文生视频 v2/v6/v7/v8 | 17.1–18.6 | 61.7–65.4 | 113.0–115.6 | 46.8–62.7 |
| **Ref2VA v9** | **6.38** ❌ | 50.1 | **90.7** ❌ | **71.9** ❌ |

纹理能量**掉到参考片的一半以下**；放大看树是纯平色块剪影、200% 零颜料肌理、干草变光滑缎带，
并且出现**黑色羽毛状伪影**（参考片与文生视频版本都没有）。参考图既没换来笔触，
也没保住主体（参考片是奶白色卷毛猫，输出仍是橘色虎斑）。

> **教训：参考图通道听起来是"更强的控制"，但如果那条通道的微调权重还是 v0.x，
> 它输出的质量上限比文生视频**低**。**
> **先读 Provider 源码里的权重文件名，再决定要不要走。**
> 参考图通道值得一试的时机：LoRA 版本号 ≥ 文生视频那条。


### 其余固定段落（这部分仍然有效）

- **光线**：一律「柔和的漫射光，没有锐利的明暗边界」——治愈系几乎没有硬光。
- **运动**：一律「微动 + 镜头极缓慢推进 / 保持静止。没有快速动作」。
- **禁止**：文字、字幕、水印、logo、卡通化的大眼睛、拟人化表情、正脸特写。
  **人物一律背影 / 侧脸 / 低头** —— 既是参考片的规则，也是规避 AI 脸部崩坏。
- **对象级排除**（唯一推荐的负向写法，见纪律 5）：
  `画面里没有任何建筑、屋顶、围墙、栅栏、招牌或红色物体`
  > 实测：只写「背景只有雪与枯枝」时模型补了红色屋顶；改成上面这句穷举式后立刻干净。

## 阶段 3：样片先行 + 缓存复用

**不要直接跑全片。** 先挑能覆盖风险象限的 4 镜做样片，约 18 分钟：

| 象限 | 验什么 |
|---|---|
| 冷暖同框 | 冷暖比例会不会失衡 |
| 纯冷 | "安静"会不会变成"空洞" |
| 生物 | **动物写实度**（最常崩的一项，实测出过卡通化的鹤头） |
| 纯暖 | 配方破例时能否真的全暖 |

### ⭐ 缓存复用技巧（省一半时间）
**Hypit 产物按内容寻址**：只要 `prompt` / `duration` / `resolution` / `aspect-ratio` **逐字一致**，跨 Run 自动命中缓存，不重复推理。

**正确姿势：先写全量 svml，再用脚本从它里面"切"出探针文件。**
手抄一份探针 prompt 极易差一个标点，缓存就废了。用脚本抽块可保证逐字节一致：

```python
# 从 authors/selected-vX.svml 抽 KEEP 指定的镜，生成 authors/vX-probe.svml
# 复用同一段 <text:Value>，只重编号 id；再校验两边逐字相等
KEEP = [1, 5, 7, 10]          # 挑高风险镜
for new, orig in enumerate(KEEP, 1):
    tv = re.search(rf'<text:Value id="p{orig}">(.*?)</text:Value>', src, re.S)
    assert A[f'p{orig}'] == B[f'p{new}']      # 必须断言相等
```
探针跑完 → 全量跑时这 4 镜直接命中缓存，**只花 8 镜的钱**。
> 反之：只要改了共用段（材质句、色板句），**全部镜的缓存都会失效**。所以共用段的调整要一次性想清楚，
> 别为了"只改一镜"而动了共用段，那等于全量重跑。

所以：**挑样片时就按象限挑，并让这 4 镜落在最终成片的镜名单里**。改提示词时只改需要改的镜，其余保持逐字不变。

校验缓存能否命中的脚本（正则提取 `<text:Value>` 逐字 diff）：
```python
import re, pathlib
def blocks(p):
    s = pathlib.Path(p).read_text(encoding='utf-8')
    return {m.group(1): m.group(2).strip() for m in re.finditer(r'<text:Value id="(p\d+)">(.*?)</text:Value>', s, re.S)}
a, b = blocks('authors/sample.svml'), blocks('authors/selected.svml')
for s, t, label in [('p1','p1','S1'), ('p4','p10','S4')]:
    print(f"{label}: {'✅ 命中缓存' if a[s]==b[t] else '❌ 已变动需重跑'}")
```

**注意**：任何改动都会让该镜缓存失效。v3 这种全局改（改尾部模板）会导致 12 镜全跑，时间预算要按全量算。

### ⚠️ 两个 svml 语法坑（写探针时踩过）
| 报错 | 原因 | 修法 |
|---|---|---|
| `pipeline:Normalize.clock has the wrong Type` | 漏了 `space:Canvas` / `program:Clock` / `space:Frame` 任一 → `clock` 未定义 | 三个声明都要在 |
| `Timeline Take source must be a SemanticTake` | `<time:Take source={m1.media}/>` 直接接了 Normalize | 必须经 `whisperx:SemanticTake` 包一层，且配 `<script>` 分段 |

### ⚠️ 本机环境两个坑（会浪费很多时间）
1. **shell 管道在 `for` 循环里会失效**：`export PATH=...` 之后在 `$(...)` 里调 `grep` / `cut` / `awk` 会报 `command not found`。
   → **凡是要解析输出的统计，改用 Python 写脚本**，不要硬拼 shell 管道。
2. **需要用 numpy/pillow 时先建隔离 venv**（本机全局没有）：
```bash
PY=/Users/wangjian/.workbuddy/binaries/python/versions/3.13.12/bin/python3
VENV=/Users/wangjian/.workbuddy/binaries/python/envs/default
[ -x "$VENV/bin/python" ] || $PY -m venv "$VENV"
"$VENV/bin/pip" install -q --index-url https://pypi.tuna.tsinghua.edu.cn/simple numpy pillow
"$VENV/bin/python" script.py
```
3. **ffmpeg 拼接时每路输入高宽必须完全一致**：`hstack`/`vstack` 只差 1 px 就会报
   `Input 1 height 241 does not match input 0 height 240`。
   → 每路都写死 `scale=W:H`（不要用 `-1` 自动保持比例）。

### BGM 挂载（成片音轨）
写在 svml 里，不是后期 ffmpeg 混：
```xml
<asset:Audio id="bgm" src="../assets/bgm-60s.wav"/>
<pipeline:Normalize id="bgm-media" source={bgm} clock={clock}
  video="none" audio="default" span-authority="audio"/>
<audio:Track id="music" timeline={program.timeline}>
  <audio:Item id="bgm-bed" source={bgm-media.media} during="program"
    playback="once" gain="1" fade-out="600ms"/>
</audio:Track>
```
各镜的 `pipeline:Normalize` 一律 `audio="none"` 丢弃模型原生音轨，成片音轨就只剩纯净 BGM。
**BGM 时长**要比镜头总时长多留 2–3 s，用 `afade=t=out` 把淡出正好落在片尾：
```bash
# 12 镜 × 124 帧 / 24fps = 62.0 s → 取 64 s，59.5 s 起淡出 2.5 s
ffmpeg -v error -i source.mp4 -vn -t 64 -acodec pcm_s16le -ar 48000 -ac 2 \
  -af "afade=t=out:st=59.5:d=2.5" assets/bgm-60s.wav -y
```

## 阶段 5：评估

### 逐镜对照图（最有效的评估工具）
每对「参考帧 / 我帧」先 `vstack` 成一组，再 `tile` 拼总图 —— **比一次性 24 输入 filter_complex 可靠得多**：
```bash
for i in $(seq 1 12); do
  idx=$(printf "%02d" $i)
  ffmpeg -v error -ss ${reftimes[$i]} -i "$REF" -frames:v 1 -vf "scale=400:225" /tmp/pair/r$idx.jpg -y
  ffmpeg -v error -ss ${ourt[$i]}    -i "$OUR" -frames:v 1 -vf "scale=400:225" /tmp/pair/o$idx.jpg -y
  ffmpeg -v error -i /tmp/pair/r$idx.jpg -i /tmp/pair/o$idx.jpg \
    -filter_complex "[0][1]vstack,pad=iw:ih+6:0:0:white" /tmp/pair/p$idx.jpg -y
done
ffmpeg -v error -start_number 1 -i /tmp/pair/p%02d.jpg -vf "tile=4x3:padding=10:color=white" -frames:v 1 -y compare.jpg
```

### ⚠️ zsh 数组下标从 1 开始
`for i in $(seq 0 11)` 配 `${arr[$i]}` 会取到空值 → `Invalid duration specification for ss: -i`。
正确写法：`seq 1 12` 配 `${arr[$i]}`。

### 评估维度
不要只看"好不好看"，要看**与参考片的系统性差**：色温 / 饱和度 / 通透度（大气透视强度）/ 构图（人物与环境面积比）。
如果在**多个镜头上都朝同一方向偏**，那是全局配方问题（改尾部模板段），不是某一镜写坏了（改主体段）。

### 客观量化（避免凭印象反复横跳）
人的眼睛在连续对比里会被"最新看到的那张"锚定，**逐版打分经常自我矛盾**。用四项指标把趋势钉住：

```bash
# ⚠️ 必须把参考片和我们的成片统一到同一个分辨率再比
# 参考片通常是 576p 级别，我们的输出是 1376×768 —— 直接比会被分辨率差异污染
# 做法：把我们的成片降到参考片原生分辨率（而不是把参考片升上去）
ffmpeg -v error -i "$OUR"  -vf scale=1024:576 /tmp/q/our.png -y
ffmpeg -v error -ss $T -i "$REF" -frames:v 1 -vf scale=1024:576 /tmp/q/ref.png -y
```
```python
# 用 numpy + pillow 算（venv: ~/.workbuddy/binaries/python/envs/default）
#   平均饱和   = PIL HSV 的 S 通道均值        → 压饱和是否到位
#   亮度对比   = 灰度图 std                   → 是否过硬（治愈系对比低）
#   纹理能量   = 拉普拉斯绝对值均值            → 笔触/画布颗粒强度
#   色相分散   = 饱和>25 的像素色相角圆标准差  → 画面是否被压成"单色"
```
**实测参考值**（冬季油画治愈片，统一 1024×576，4 组配对镜平均）：

| 样本 | 纹理能量 | 亮度对比 | 平均饱和 | 色相分散 |
|---|---|---|---|---|
| **参考片** | 14.40 | 55.4 | **109.7** | **68.5** |
| v2 | 13.93 | 64.7 | 91.4 | 66.7 |
| v5 探针 | **14.45** ✅ | 61.1 | **81.3** ❌ | **56.8** ❌ |

**控制实验（必做）**：把参考片原生 1024×576 与上采样 1376×768 各算一遍，
饱和度指标完全一致（109.7 vs 109.7）→ **该指标与采样分辨率无关**，可以直接横向比。
纹理能量则**与分辨率强相关**，所以纹理一律在同分辨率口径下比。

### ⚠️⚠️ 血泪教训：**参考片往往比你以为的更饱和**
本次我先凭观感判断"参考片低饱和、我们偏艳"，于是连续两版加码降饱和——
量化后发现**方向完全反了**：参考片 S=109.7，v2 只有 91.4，v5 更降到 81.3。

**"看着像数字插画"的真实成因不是饱和度**，而是这四项的任意组合：
1. **笔触尺度太小**（细节齐全、物体轮廓完整）→ 纪律 9 ⭐ 最根本
2. **笔触均匀铺满**（缺远近梯度）→ 纪律 8
3. **色相范围宽**（画面里什么颜色都有几块）→ 参考片是"窄色相 + 中饱和"
4. **全局对比过高** → 亮度对比 64.7 vs 参考片 55.4

**参考片的配方是「窄色相 + 中饱和 + 低对比 + 强大气透视」，不是「低饱和」。**
降饱和过度会同时损失固有色层次（色相分散从 68.5 掉到 56.8），画面变得灰死。
**色彩段的正确写法是「保留固有色与明暗层次，只是统一压在某个色调里」，而不是「所有颜色都掺灰」。**

### 分色占比：定位"哪个颜色入侵了"的最快手段
```python
# 按色相切区间统计像素占比（%），比肉眼看对照图准得多
#   红 0–16° & 340–360° / 橙 16–45° / 黄 45–75° / 绿 75–165° / 蓝 165–270°
#   高饱和占比 = S>140 & V>60 的像素比例  → "艳俗感"的直接指标
```
实测：S1 车站镜里参考片橙 17.9%、蓝 32.3%，而 v5 出片橙 0.1%、蓝 56.4%
→ 一眼看出「暖色被清空、画面变单色」，同时也能抓到**未被计入橙区的鲜红元素**（红围巾）。

### ⚠️ 纹理/质感类指标要限定在"天空"等平坦区
在平坦区（天空、雪面）测高频能量才能反映**笔触/画布颗粒**；在全图上测会被主体边缘和构图差异淹没。
但注意：**取横带做"远/近"对比会踩构图坑**——溪流镜的上三分之一是树冠不是天空，
"远带"反而比"近带"纹理更高。要判大气梯度必须**手工裁真正的天空/远景区**，不能按 y 坐标机械切带。

## 阶段 6：后处理补笔触 —— 提示词通道探到边界之后 ⭐⭐

**什么时候走到这一步**：纪律 12/13 都试过了（文生视频的加法型杠杆用尽、参考主体通道权重是 v0.1），
画面仍是「精致数字插画」。此时差距只剩**笔触的物理尺度**，它在模型先验里，改不动。
**最后一层只能在成片之后补。**

参考实现：`productions/oil-painting-replica/tools/oil_post.py`（OpenCV，约 0.19 s/帧）。

### 先看清目标：参考片的微观结构到底是什么

**必做第一步**：裁 3 块局部放大 **3×**（不是 100%，是 300%）——平面 / 主体 / 平坦区各一块。
实测一块油画风参考片在 3× 下是：

- **大片近乎平色的色块**（块内方差极小）
- **柔边的长拉丝**（长宽比 10–20:1，低对比，顺着形体走）
- **低对比、强雾化**
- ❌ **不是**铺满画面的均匀颗粒 / 画布织纹

> ⚠️ **我一开始搞反了**：以为缺的是"颗粒/织纹"，于是叠了一层均匀高频噪声 +
> 程序化画布织纹。结果得到的是**版画/梵高涡旋**，不是油画。
> **颗粒 ≠ 厚涂。厚涂是"平色块 + 拉丝脊"。**

### 四层管线（各层独立可关，逐层加、逐层看）

| 层 | 做法 | 关键点 |
|---|---|---|
| 1 **压平** `flat` | **各向同性** Kuwahara | ⭐ 用 `cv2.boxFilter` + `copyMakeBorder` 实现，**O(1) 与半径无关** → k 开到 24–48 仍只 0.2 s/帧，这是"大色块"能做出来的前提。**别用定向细长核**（aspect>1.5）——那会抹成水彩晕染 |
| 2 **拉丝** `streak` | 结构张量算流向 → 沿流向做 **LIC**（`cv2.remap` 迭代）把白噪声拉成丝，当高度场 | 流向 = **垂直于梯度**（沿形体）。`streak_scale < 1` 在低分辨率生成再放大 = **笔脊变宽**，这是控制笔触宽度的主杠杆；全分辨率生成 = 版画细刻 |
| 3 **堆料** `relief` | 高度场做 Lambert 浮雕着色，按亮度乘性叠加 | 幅度要小（0.2–0.4）。**不要另加画布织纹** |
| 4 **收色** `palette` | Lab 空间把统计量拉向该镜的参考帧 | 见下面两个坑 |

定稿参数（溪流/橘猫两镜四项指标都逼近参考片；12 镜全片实测 5m06s / 0.33 s/帧）：
```bash
python oil_post.py video --in in.mp4 --out out.mp4 \
  --refs "1=refs/s01.png,2=refs/s02.png" --shot-seconds 5.1667 \
  --flat 6 --streak 1.2 --streak-steps 22 --streak-step 5.0 --streak-scale 0.12 \
  --flow-sigma 22 --relief 0.55 --palette 0.70 --chroma-std 0.2
```
> 参数演进：先定到 `flat 10 / streak 0.8 / relief 0.30`（四项指标已过关），但**纹理能量只有 8.10**
> （参考片 14.65）—— 笔脊偏弱。把压平降到 6、拉丝升到 1.2、堆料升到 0.55 后纹理回到 13.9，
> 其余三项不掉。**纹理能量偏低 = 笔脊不够，几乎总是"堆料/拉丝给少了"，而不是"压平不够"。**

### ⚠️ 必做验收：时间稳定性（后处理会引入逐帧闪烁）

流向场是**逐帧从图像算出来的**，压平 + 拉丝都是逐帧独立操作 → 天然有闪烁风险。
**必须抽一段静感最强的镜头（如静态风景）做逐帧差测试**：

```python
# 抽 48 帧 → 分别对原始素材和两套参数成片算 |帧间灰度差| 均值
```
实测（溪流镜 48 帧）：原始 v8 **5.780** / 弱参数版 3.046 / 强参数版 **3.889**。
→ 两版**都比原始素材更平稳**（压平 + 拉丝平滑了时间噪声），**可以放心加力**。
判据：**后处理的逐帧差不应显著高于原始素材**；若高一截，说明笔触在"游动"。

### 前提条件：先把全量原片跑出来

后处理是**逐帧无记忆**的，它只会放大输入已有的形态，**不会创造主体结构**。
所以顺序必须是：**先全量重跑配方修内容问题（构图/主体/配色），再上后处理**。
反例：本项目曾想直接在 v2 成片上做后处理，但 v2 的 S1 是 3D 动画风、S7 是超写实照片风 ——
后处理救不了内容层面的错。先跑 v8 全量（55 min）把这两镜修掉，后处理才有意义。

### ⚠️ 两个把结果搞砸的坑（各花了一次半小时）

1. **整数/浮点混用**：收色函数写成 `cv2.cvtColor((np.clip(ref,0,1)*255).astype(uint8), …)`，
   而 `ref` 从 `cv2.imread` 来已经是 **uint8 0..255** → `np.clip(ref,0,1)` 把它截成**二值图** →
   参考统计量全废（对比 73→32、饱和 63→12.8）。
   **规矩：写一个 `_u8()` 统一入口，对已经是 uint8 的图不要再 `*255`。**

2. **a/b 通道做全量标准差匹配（Reinhard）会反噬**：
   对"本来就准"的镜（橘猫 色相分散 12.6 vs 参考 9.1），全量匹配把它推到 25 —— 因为
   色度 std 匹配会**放大色度噪声**。
   **正确做法：L 通道全量（均值+标准差）；a/b 只对齐均值 + 少量标准差（`chroma_std≈0.2`）。**
   改完之后溪流 37.2 / 橘猫 12.8，两个镜都对上了。

### 调参必须数字 + 微观同时看

只看肉眼容易越调越"艺术"但离参考片越来越远（我有一版视觉很好、纹理能量只剩参考片的 28%）。
回路：`oil_post.py still` 出图 → `eval_still.py` 看四项指标 → `micro_compare.py` 看同区 3× 结构。
**两个都过才算过。**

> `eval_still.py` 与 `pair_metrics.py` 用同一套公式，所以静帧调参的结果可以直接外推到整片。

### 元教训：**遇到问题时，先怀疑"我加的东西"，而不是"我加得不够"**
v3 的失败模式是：发现 v2 偏暖偏艳 → 加大量的约束 → 更糟。
**正确顺序是**：(1) 先做小规模探针（2–3 镜，15 分钟）验证单一变量；(2) 一次只改一个杠杆；(3) 保留上一版作者文件做对照。
**永远不要在一次构建里同时改 5 个变量** —— 那样拿到坏结果也不知道该退回哪一步。

### 元教训二：**同提示词重跑结果高度可复现 → 单变量 A/B 可信**
实测：同一段 267 字提示词跑两次，平均饱和 0.227 vs 0.228、平均亮度 139.9 vs 139.6、色彩数 2322 vs 2357。
**在随机波动范围内。**
意义有两层：
1. 做单变量对照实验是**可信**的，差异就是提示词造成的，不是抽样噪声；
2. 反过来，如果两版的结果差异**很大**，那一定是提示词改了，**别归因给"运气不好"**。

### 元教训三：**"没有改善"和"我误读了"要先分清**
本次绕了三轮，其中一轮是因为把"缩略图上看不见"当成了"东西不存在"。
下结论前先问：**我是在什么尺度上看的？这个尺度能不能承载我要判断的特征？**（纪律 10）

### 元教训四：⭐ **"看着艳/看着灰"这类整体观感，必须先用数字定位再动手**
本次最大的一次弯路：凭观感断定"参考片低饱和、我们偏艳偏锐"，连续两版加码降饱和，
量化后发现**方向完全相反**（参考片 S=109.7 > v2 91.4 > v5 81.3），把画面越调越死。

**正确顺序**：
1. 先跑量化（饱和度 / 亮度对比 / 纹理能量 / 色相分散），**把参考片和我们放在同一口径下**
2. 找出**偏差最大的是哪一项**——本次真正超标的其实是对比度（64.7 vs 55.4）和纹理均匀性，不是饱和度
3. 只针对那一项改配方，再探针验证

> **观感负责提出假设，数字负责裁决。** 把"整体偏X"这种模糊判断直接翻译成提示词改动，
> 是本次绕了四轮的根本原因。

### 元教训五：**探针要用脚本从全量文件里"切"出来，不要手写**
手写探针文件会（a）抄错字导致全量跑时缓存不命中，（b）漏掉 `Canvas` / `Clock` / `Frame` 等声明。
用正则从 `selected-vX.svml` 里抽出目标镜的 `<text:Value>` 与 `<h3:TextVideo>`，
只重编号 id，然后**断言两边字符串逐字相等**。这样探针结果可以直接并入全量，只付一次推理钱。

### 元教训六：⭐ **一个 prompt 内部会"打架"——先查冲突，再查力度**
指令没生效时，第一反应通常是"我写得不够重"，于是加码、加长、加形容词。
但 v7 的教训是：**材质层和主体层写了互相矛盾的指令，加码只会让矛盾更僵。**

排查顺序应改成：
1. **先扫关键词找冲突**（`写实` `清晰可辨` `细密` `每一根` `逐根` `细腻` 出现在主体层 = 在要求细节完整）；
2. 再判断是不是"说反了"——想要 A，但主语段里描述的是 ¬A 的成因；
3. 最后才考虑加大力度。

> 同一个 prompt 里，**离物体越近的陈述优先级越高**。全局风格声明（材质层）永远会被
> 局部事实陈述（主体层）否决。所以风格要生效，**必须在两层都写同一个方向**。
>
> ⚠️ **但 v8 把这个机制证伪了**：两层都写成同一个方向（8 处全改），结果零变化。
> 机制不是假的，是**剂量不够**——真正的决定因素是模型对命名主体的细节先验。
> 所以排查顺序实际上应该是：
> **① 是不是"多了什么"？→ 换通道（纪律 13），别碰提示词。** ② 才是找冲突、③ 才是加力度。

### 元教训七：⭐⭐⭐ **把问题分成"多了什么 / 少了什么"，两类用完全不同的手段**

这是 12 个版本跑下来最省时间的一条分类法。

| 问题形态 | 例子 | 有效手段 | 无效手段 |
|---|---|---|---|
| **多了什么** | 细节太齐全、太锐、杂色入侵、笔触太细 | **换通道**（Ref2VA 参考主体 / 首尾帧）、指定关键物体颜色 | 否定清单、省略类措辞 |
| **少了什么** | 缺雾、缺光比、饱和过低、色相被压成单色 | 加法型正向句、排他白名单、梯度描述 | 换通道 |

> 判断方法：先问"我要消除的东西，是不是**模型自己生成出来的**？" 是 → 它在训练先验里，
> 文字推不动它，只能换一条不走那个先验的通道。
> 反过来，如果缺的东西是**模型不会主动生成**的（雾、光比、排他色板），那才轮到提示词上场。

## 项目文件组织（沿用）

```
productions/<name>/
  BRIEF.md              # 委托：目标、硬约束、预算
  TREATMENT.md          # 创作答案：结构、选镜逻辑
  PROGRESS.md           # 当前状态 + 逐镜评估 + 待办
  look.svs              # 全局呈现层样式
  references/source/    # source.mp4 + ANALYSIS.md + TIMELINE.md + evidence/
  authors/*.svml        # 作者文件（每轮一版，不覆盖旧的）
  runs/*.svrun          # run 文件
  assets/               # BGM 等
  drafts/               # 成片 + 对照图 + 抽帧网格
```
**每轮改版另存新文件**（`selected.svml` → `selected-v3.svml`），旧版留档可回溯对比。
